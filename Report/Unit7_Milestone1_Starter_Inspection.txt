   1: """
   2: Signal one: the model signal.
   3: 
   4: This is the signal that "reads the text for meaning". It runs a language model
   5: on your own machine and asks one question: **how predictable is this text?**
   6: 
   7: The idea is the one every AI-detection product is built on. A language model
   8: writes by repeatedly picking a likely next word, so text a model produced tends
   9: to be text a model finds easy to predict. Human writing wanders more â€” odd word
  10: choices, abrupt turns, the specific rather than the typical.
  11: 
  12: The measure is called **perplexity**. Low perplexity means "I could have
  13: guessed this"; high perplexity means "that surprised me". This module turns
  14: that into a 0â€“1 score where **higher means more likely AI**.
  15: 
  16:     from detector import model_signal
  17:     score = model_signal("some text")     # 0.0 human-ish â€¦ 1.0 AI-ish
  18: 
  19: Everything runs locally. No account, no key, no card.
  20: 
  21: âš ï¸ **The blind spot, which you have to name in Milestone 1.**
  22: 
  23: Predictability is not the same thing as authorship. What this signal actually
  24: rewards is **common words in short, ordinary sentences** â€” and plenty of real
  25: people write that way.
  26: 
  27: Someone writing in a second language, sticking to vocabulary they're sure of.
  28: A younger writer. Anyone writing plainly on purpose. Measured against gpt2,
  29: writing like that scores about as machine-like as machine writing does.
  30: 
  31: The reverse trips people up too: dense, ornate prose full of rare words often
  32: scores as *human* on this signal, because rare words are exactly what a
  33: language model fails to predict. Formality on its own doesn't decide it.
  34: 
  35: So the writers this signal is most likely to accuse are the ones with the
  36: least room to argue back. That is structural rather than a bug you can fix,
  37: and it is the person Milestone 1 asks you to follow through your service.
  38: 
  39: Don't take that on trust â€” it's a claim you can check. Milestone 4 has you run
  40: four calibration inputs. Add a plainly-written human paragraph to them and see
  41: for yourself where it lands.
  42: """
  43: 
  44: import math
  45: 
  46: import config
  47: 
  48: _model = None
  49: _tokenizer = None
  50: 
  51: 
  52: class DetectorUnavailable(RuntimeError):
  53:     """The model couldn't be loaded â€” no download yet, or no disk."""
  54: 
  55: 
  56: def _load():
  57:     """Load the model once and keep it. First call downloads ~550 MB."""
  58:     global _model, _tokenizer
  59:     if _model is not None:
  60:         return _model, _tokenizer
  61: 
  62:     try:

  64:         from transformers import AutoModelForCausalLM, AutoTokenizer
  65:     except ImportError as exc:

  67:             f"transformers or torch isn't installed ({exc}).\n"
  68:             f"Run: pip install -r requirements.txt"
  69:         ) from exc

  71:     try:

  73:         _model = AutoModelForCausalLM.from_pretrained(config.DETECTOR_MODEL)
  74:         _model.eval()
  75:     except Exception as exc:  # noqa: BLE001
  76:         raise DetectorUnavailable(
  77:             f"Couldn't load '{config.DETECTOR_MODEL}': {exc}\n"
  78:             f"The first run downloads about 550 MB â€” check your connection and "
  79:             f"that you have disk space free."
  80:         ) from exc
  81: 
  82:     return _model, _tokenizer
  83: 
  84: 
  85: def perplexity(text: str) -> float:
  86:     """
  87:     How surprised the model is by this text. Lower means more predictable.
  88: 
  89:     Returns a positive number. Typical values land roughly between 10 and 200,
  90:     but that range shifts with topic and length, which is one reason the raw
  91:     number isn't what you score on.
  92:     """
  93:     import torch
  94: 
  95:     model, tokenizer = _load()
  96: 
  97:     encoded = tokenizer(
  98:         text,
  99:         return_tensors="pt",
 100:         truncation=True,
 101:         max_length=config.DETECTOR_MAX_TOKENS,
 102:     )
 103:     input_ids = encoded["input_ids"]
 104: 
 105:     # Two tokens is not enough to be surprised by anything.
 106:     if input_ids.shape[1] < 3:
 107:         raise ValueError("Text is too short to score â€” a few sentences at least.")
 108: 
 109:     with torch.no_grad():
 110:         output = model(input_ids, labels=input_ids)
 111: 
 112:     # The model's loss here IS mean negative log-likelihood per token.
 113:     return float(math.exp(output.loss.item()))

 116: def model_signal(text: str) -> float:
 117:     """
 118:     The signal, as a 0â€“1 score. **Higher means more likely AI.**
 119: 
 120:     Perplexity is unbounded and roughly log-distributed, so it gets squashed
 121:     onto 0â€“1 rather than clipped. The midpoint below is the perplexity that
 122:     maps to 0.5 â€” text this surprising is a coin flip.
 123: 
 124:     You may want to move that midpoint once you've run the four calibration
 125:     inputs in Milestone 4 and seen what your own text actually scores. If you
 126:     do, say so in your README: it's a scoring decision, not a detail.
 127:     """
 128:     ppl = perplexity(text)
 129: 
 130:     midpoint = 45.0    # perplexity that scores 0.5
 131:     steepness = 1.6    # how sharply the score moves either side of it
 132: 
 133:     # Logistic on log-perplexity. Low perplexity -> high AI score.
 134:     score = 1.0 / (1.0 + (ppl / midpoint) ** steepness)
 135:     return round(min(max(score, 0.0), 1.0), 4)

 160: 1. In `config.py`, set `RATE_LIMITING_ENABLED = True` â€” or run with
 161:    `AI201_RATE_LIMITS=1`.
 162: 2. Choose your numbers there.
 163: 3. In `app.py`, uncomment the `@limiter.limit(...)` line above `submit`.
 164: 
 165: Then push past your limit and watch for `429`:
 166: 
 167: ```bash
 168: python run_attacks.py --flood 15
 169: ```
 170: 
 171: That sends 15 submissions from one `creator_id` and prints the run of status
 172: codes â€” `200 200 200 ... 429 429` â€” which is exactly what your README's **Rate
 173: Limiting** section asks you to paste. It also writes `results/flood_<date>.md`.
 174: 
 175: The attack set can't do this for you. Every attack row submits under its own
 176: `creator_id`, so a full attack run looks like forty-odd different callers and
 177: never trips a limit however long it is.
 178: 
 179: No `429` at all? Either your limit is above 15 a minute, or rate limiting is
 180: still off. `GET /health` reports which.
 181: 
 182: Rejections are logged for you. **An attack that shows up only as an absence is
 183: one you'll never find** â€” a thousand requests that got a `429` and left no
 184: trace look exactly like a quiet afternoon.

 188: ## Running it somewhere else (unit 9)
 189: 
 190: Unit 9 asks you to deploy one of your systems. **Read this before you pick
 191: which one** â€” for this project the answer is already decided, and it isn't the
 192: hosted one.
 193: 
 194: Flask's built-in server says "development server" on startup because that's
 195: what it is. A real one comes from `gunicorn`, which is in
 196: `requirements.txt` and unused until now:
 197: 
 198: ```bash
 199: gunicorn app:app --bind 0.0.0.0:$PORT
 200: ```
 201: 
 202: Two settings do the work, and both read the environment:
 203: 
 204: | Variable | Default | What it does |
 205: |---|---|---|
 206: | `HOST` | `127.0.0.1` | Loopback â€” your machine only. A host needs `0.0.0.0`, or nothing outside the box can reach the service and it looks like the app is down |
 207: | `PORT` | `5000` | Most hosts hand you a port in `PORT` and expect you to bind exactly that one |
 208: | `AI201_DEBUG` | `1` | Debug mode. Off automatically whenever `HOST` isn't loopback â€” an interactive debugger on a public address is a stranger's Python prompt inside your process |
 209: 
 210: Nothing about your local workflow changes. With no variables set you get
 211: `http://127.0.0.1:5000` and every `curl` above still works.
 212: 
 213: ### This project will not fit a free host
 214: 
 215: Say it plainly, because the arithmetic is the point:
 216: 
 217: | What has to be in memory | Roughly |
 218: |---|---|
 219: | `torch` | ~200â€“800 MB depending on the build |
 220: | the `gpt2` weights | ~550 MB on disk, loaded into RAM to score |
 221: | Flask, gunicorn, your code | the rest |
 222: | **A free tier gives you** | **512 MB** |
 223: 
 224: That's over budget before a single request arrives â€” and a free host has no
 225: persistent disk, so the 550 MB download starts again after every idle
 226: spin-down. There is no configuration that fixes this. The model is the size it
 227: is.
 228: 
 229: **So pair 4 extensions take Path B â€” local, with logs.** That is the expected
 230: answer for this project, not a fallback and not a failure. Working out that a
 231: system doesn't fit its host *before* you spend an evening watching it get
 232: killed is the skill unit 9 is actually testing. Write the arithmetic above in
 233: your write-up; that's the deliverable.

 256: ## The two blind spots, up front
 257: 
 258: Both signals have one, and unit 8's attack set is built out of them. You have
 259: to name them yourself in Milestone 1 â€” but knowing they exist now saves you
 260: from being surprised.
 261: 
 262: **Signal one** measures how *predictable* your text is. Predictability isn't
 263: authorship. What it really rewards is common words in short, ordinary
 264: sentences â€” someone writing in a second language and staying with vocabulary
 265: they're sure of, a younger writer, anyone writing plainly on purpose. Writing
 266: like that scores about as machine-like as machine writing does. (Dense, ornate
 267: prose often goes the other way and reads as human, because rare words are what
 268: a language model fails to predict.) So the writers this signal is most likely
 269: to accuse are the ones with the least room to argue back. That is the false
 270: positive the whole project is about, and it's structural rather than a bug.
 271: 
 272: **Signal two** cannot read. It has no idea what the text says. Anything that
 273: changes the shape without changing the substance moves it â€” typos, broken-up
 274: sentences, a pasted quotation. That is very cheap to do on purpose.

 278: ## When something goes wrong
 279: 
 280: | What you see | What it means |
 281: |---|---|
 282: | `501 not_implemented` | Correct at the start â€” that's the TODO in `app.py` |
 283: | `404` from curl | Is the server running? Is the path exactly what you typed? |
 284: | `Cannot bind parameter 'Headers'` | You're in PowerShell, where `curl` is a different tool. Use `curl.exe`, on one line |
 285: | Request body arrives empty | curl needs `-H "Content-Type: application/json"` |
 286: | `Address already in use` | A server left running from an earlier attempt. Kill it, don't debug it |
 287: | The first submission takes 10+ seconds | Signal one is loading the model into memory. Later ones take a second or two |
 288: | *Every* submission takes 10+ seconds | Something is reloading the model each call. `GET /health` shows `detector_loaded` â€” if it goes back to `false`, look for a reload in your handler |
 289: | `DetectorUnavailable` | Run `python detector.py` once to download the model |
 290: | `/appeal` seems to do nothing | Does the `content_id` you sent actually exist in the log? A typo there fails silently |
 291: | Every request gets through, no `429` ever | The decorator is uncommented but limiting is still off. Set `RATE_LIMITING_ENABLED` in `config.py` |
 292: | Flask-Limiter warns about storage | Shouldn't happen â€” `storage_uri` is preconfigured. If you changed it, put it back |
 293: | All three of your labels never appear | Your ranges have a gap. `scoring.label_ranges()` prints them |
 294: 
 295: If the route won't respond, go back to `/ping`. If that answers, the problem is
 296: in your handler.
